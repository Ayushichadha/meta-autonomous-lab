# Repository audit and implementation priorities

Baseline inspected November 1, 2026, before the sequential-twin extension. Existing simulator, domain models, scheduling, validator, tools, provider clients, CLI, web server/assets, tests, manifests, and documentation were reviewed. The existing dashboard was browser-checked during its implementation; its current source and data contract were reviewed again.

## Baseline evidence

- 22 automated tests pass locally, including the newly implemented credit guard.
- One real Meta Muse Spark 1.3 recovery decision succeeds: three experiments, three model requests, a validated rerouting selection. Approximate token cost: $0.01988.
- The first small smoke call exhausted its output cap; a forced tool-choice attempt was rejected because Meta only supports `auto`. The corrected automatic-choice smoke test succeeds. These failures are not hidden; unknown usage reservations remain in the local ledger.
- A local $1 estimated-dollar allowance, prompt/output caps, per-client request limit, and no automatic retries constrain development costs. Model calls are not part of the ordinary unit tests.

## Working foundations to preserve

Typed scenario and progress models; explicit routing durations; CP-SAT feasible schedules; a solver-independent plan checker; partial SimPy execution; bounded experiment tools; recorded solver statuses; synthetic-input labels; GitHub CI; and a local dashboard with meaningful outputs.

## Gaps and risks

1. **P0: One decision, not an evolving twin.** A sequence runner must separate hidden physical events from observed repair estimates, execute between updates, and retain started work.
2. **P0: Queue fidelity under delays.** The replay currently waits for job dependencies before requesting a machine, which can let later queued work overtake blocked work. A submitted queue must remain explicit until a recovery action changes it.
3. **P0: Weak state validation.** Progress should also reject impossible elapsed work and overlapping historical machine occupancy.
4. **P0: Forecasts dominate reporting.** Sequential results must distinguish candidate forecasts from realized outcomes and retain failures.
5. **P1: No policy benchmark.** Single-event comparisons are not evidence of learned/adaptive superiority. Add preserve, always-replan, fixed-interval, exhaustive candidate-selection, and Meta policies under shared information and budgets.
6. **P1: Missing observability.** Add decision-time states, event history, candidate requests, action/compute accounting, and recorded-versus-live labels to the console.
7. **P1: No held-out evidence.** Freeze configuration and generator/seeds before evaluation; publish every attempted scenario. Do not call development seeds held-out.
8. **P2: No justified advanced actions yet.** State inspection and explicit experiment hypotheses are a useful near-term extension. Defer broad optimization parameter search and infrastructure integrations.

## Delivery sequence

1. Commit real-inference evidence and cost controls.
2. Implement an event-driven episode runner with confirmed outages/repairs, estimate changes, resumable execution, and independent checks; test offline.
3. Integrate the supervisor with sequential decisions, observed history, inspection tools, and explicit failure fallback. Verify one small live episode under the credit guard.
4. Freeze baseline and evaluation contracts, run at least 20 offline seeded scenarios, then run a bounded live subset or full agent evaluation only within the existing allowance. Explicitly publish coverage and failures.
5. Upgrade the existing console around real episode/evaluation artifacts and verify browser behavior.
6. Document reproduction, measured results, limitations, and a truthful three-minute demo flow.

The November 4 submission target leaves roughly three building days plus final packaging. Correct discrete-event execution and a reproducible end-to-end demo take precedence over visual scope. This remains a simulation-based twin prototype; there is no claim of synchronization with an operating factory.
